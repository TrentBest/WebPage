# Living GUI Documentation Coverage

> This is the rollout ledger for the requirement that every WebPage guide and theory document carries a living-GUI entry point and a subject-specific visual/evidence path. It records actual source changes—not aspirations.

![Living GUI documentation lens: question, model, implementation, visible manifestation, and proof](https://raw.githubusercontent.com/TrentBest/WebPage/development/docs/assets/living-gui-documentation-lens.svg)

The animated lens is an **architecture illustration, not runtime telemetry**. A page is not fully covered merely because it embeds this image: it must also point to a relevant view, source, deterministic fixture, browser journey, or test, and clearly label anything proposed or illustrative. See [Documentation Standard](DOCUMENTATION_STANDARD.md) and [Diegetic WYSIWYG and Living Documentation](DIEGETIC_WYSIWYG_AND_LIVING_DOCUMENTATION.md).

**Coverage rule:** “Embedded” means the shared lens is present. It does not claim that the subject-specific visual audit is complete. “Pending” means the shared lens has not yet been inserted into that document.

## Completion gates

- [ ] Shared lens embedded in every listed document.
- [ ] Subject-specific living view, source/fixture/test link, and evidence class audited for every document.
- [ ] New/changed documentation is checked automatically for lens and evidence metadata.
- [ ] Visuals checked for accessibility, reduced motion, narrow screens, and dark/light contrast.

This coverage ledger is intentionally stricter than an image count. The north star remains: **the reader should be able to inspect the model, witness the behavior, trace the evidence, and use the same underlying representation to create something of their own.**
